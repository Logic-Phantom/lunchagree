# 장소 데이터 정책

1. **저장 가능한 데이터만 방에 저장한다.** 방의 `candidates`에는 공공데이터 샤드에서 고른 항목(`PUBLIC_DATA`, 장소 ID·이름·주소·좌표·종류)과 참가자가 직접 입력한 항목(`MANUAL`)만 들어간다.
2. **카카오·네이버 장소 API는 쓰지 않는다(MVP).** 카카오 로컬은 응답 원본·가공 데이터의 기기·서버 저장, 20분 임시 저장도 불가하다는 공식 답변(프롬프트 §1·§3-1). 네이버는 저장 조건 미확인. Phase 6에서 "저장 없이 실시간 표시"만 가능한 설계일 때 약관 재확인 후 검토.
3. **지어내지 않는다.** 가격·영업시간·평점·메뉴·사진을 만들지 않는다. 가격은 참가자가 입력한 값만 "직접 입력"으로 표시하고, 없으면 "가격 미확인". 종류 태그가 업태가 아닌 이름 규칙에서 나온 경우 "(추정)".
4. **식당 사진·로고·메뉴판 이미지를 쓰지 않는다.** 빈 자리는 음식 종류를 나타내는 자체 그림(`FoodThumb`).
5. **외부 지도 앱 링크**(카카오맵·네이버지도 검색)는 앱인토스 허용 여부 확인 전까지 넣지 않는다. 결과 공유 문구에 주소를 넣는 것으로 대신한다.
6. **상호**는 공공데이터 사업장명을 그대로 보여 주고, 실제 간판명과 다를 수 있음을 고지한다.
